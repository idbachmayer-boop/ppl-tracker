<conventions_from_05_01>
Binding on this plan. Full rationale in 05-01-PLAN.md `<decisions_recorded>`.
- Markup carries `data-action="<literal name>"` plus `data-*` args. Every interpolated `data-*`
  value is `${esc(…)}`. Action names are never interpolated.
- An `ACTIONS` entry is `name: { <event>: (el, e) => … }`. A wrapper decodes `data-*`, reads numeric
  keys (`i`, `k`, `idx`, `n`, `d`, `range`) with `+el.dataset.key`, and calls the existing function
  with its existing arguments and arity. It never mentions `DB` and never calls `save()`/`saveLocal()`.
- Block-level converted targets become `<button class="… tap">`, and inline ones
  `<button class="tap-inline">`. Keep classes and inline styles. Inner `<div>`s become `<span>`s with
  `display:block` merged into their style, and a `kicker()` call inside becomes `kicker(…, 'span')`.
- On every rewritten template line, other `${…}` attribute values carrying stored or user data get
  `esc()` too (D-09), with the one exception this plan's prohibitions name.
- Existing actions to reuse: `go` (`data-tab`), `goSub` (`data-tab`, `data-sub`), `exportData`,
  `enter` (`data-enter`), `logWeight`, and `logPetWeight` (`data-input`, optional `data-date-el`).
- For every converted row, set `action`/`actions` in `test/fixtures/handler-inventory.json`. Never
  change the identity fields.
- Test helpers: `controlsIn`, `fakeEl`, `fireAction`, `spyOn`, `f2Corpus()`, `populatedDB`,
  `fullDraft`, and the lawn `setup(a, o)`.
</conventions_from_05_01>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| program and option names, to-do indexes → Today markup | Names are program constants. The pet name is user-controlled and reaches a placeholder. |
| keydown on an input → a click action | Enter-to-log crosses event types (the `enter` action). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-02 | Tampering (XSS) | `startWorkout('${o.name}')` / `skipDay('${nxt}')` today, and the pet name in the weigh-in placeholder | medium | mitigate | Names move to `data-name="${esc(…)}"`. The pet-name placeholder keeps its existing `esc(petName())` at the call site, and `logRow` does not double-escape it (prohibition plus an acceptance grep). |
| T-5-14 | Denial of Service (data) | a double-logged weigh-in or to-do from Enter plus click | medium | mitigate | `keydown` exists only on `enter`, on inputs. The Task 2/3 tests prove one log per Enter, one per tap, and none from a keydown on the button. |
| T-5-15 | Denial of Service (data) | a mobility stretch toggled twice by label forwarding | medium | mitigate | The action is on the checkbox (`change`), never on the label, proven in Task 2. |
| T-5-SC | Tampering | npm/pip/cargo installs | high | accept | Nothing is installed in this phase. |
