<conventions_from_05_01>
Binding on this plan. Full rationale in 05-01-PLAN.md `<decisions_recorded>`.
- Markup carries `data-action="<literal name>"` plus `data-*` args. Every interpolated `data-*`
  value is `${esc(…)}`. Action names are never interpolated.
- An `ACTIONS` entry is `name: { <event>: (el, e) => … }`. A wrapper decodes `data-*`, reads numeric
  keys (`i`, `k`, `idx`, `n`, `d`, `range`) with `+el.dataset.key`, and calls the existing function
  with its existing arguments and arity. It never mentions `DB` and never calls `save()`/`saveLocal()`.
  `this` becomes `el`, `this.value` becomes `el.value`, and `event` becomes `e`.
- Block-level converted click targets become `<button class="… tap">`, and inline ones
  `<button class="tap-inline">`. Keep the existing classes and inline styles. Inner `<div>`s become
  `<span>`s with `display:block` merged into their existing `style`.
- On every template line you rewrite, every other `${…}` inside an attribute value that carries
  stored or user data also gets `esc()` (D-09).
- For every row you convert, set `action` (or push into `actions`) in
  `test/fixtures/handler-inventory.json`. Never change `fn`, `event`, `tag`, `was`, `occurrence` or
  `calls`.
- Test helpers from 05-01: `controlsIn(html)` returns `{tag, type, cls, disabled, data}`;
  `fakeEl(data, extra)`; `fireAction(a, type, el, more)`; `fireListener(…)`; `spyOn(a, name)`;
  `f2Corpus()`, where new states are appended under its "States later plans add" comment. Every new
  test uses a fresh `loadApp` instance, never the shared `app`.
</conventions_from_05_01>
