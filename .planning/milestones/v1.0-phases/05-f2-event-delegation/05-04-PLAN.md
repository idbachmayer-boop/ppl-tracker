<conventions_from_05_01>
Binding on this plan. Full rationale in 05-01-PLAN.md `<decisions_recorded>`.
- Markup carries `data-action="<literal name>"` plus `data-*` args. Every interpolated `data-*`
  value is `${esc(…)}`. Action names are never interpolated.
- An `ACTIONS` entry is `name: { <event>: (el, e) => … }`. A wrapper decodes `data-*`, reads numeric
  keys (`i`, `k`, `idx`, `n`, `d`, `range`) with `+el.dataset.key`, and calls the existing function
  with its existing arguments and arity. It never mentions `DB` and never calls `save()`/`saveLocal()`.
- Block-level converted targets become `<button class="… tap">`, and inline ones
  `<button class="tap-inline">`. Keep classes and inline styles. Inner `<div>`s become `<span>`s with
  `display:block` merged into their style.
- On every rewritten template line, other `${…}` attribute values carrying stored or user data get
  `esc()` too (D-09).
- For every converted row, set `action` in `test/fixtures/handler-inventory.json`. Never change the
  identity fields.
- Test helpers: `controlsIn` (it reports `disabled`), `fakeEl` (pass `{ disabled: ctrl.disabled }`
  through to model a disabled button), `fireAction`, `spyOn`, `f2Corpus()`, `HOSTILE`, `populatedDB`
  and `fullDraft`. The harness element stub has `setSelectionRange` (05-02), which `editJournal` needs.
</conventions_from_05_01>
