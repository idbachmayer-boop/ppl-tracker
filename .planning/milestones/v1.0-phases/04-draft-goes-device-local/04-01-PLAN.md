<objective>
Lead the phase with one thin, production-quality path through every layer it changes, then close
every other door the draft could leave by.

Path: Ian types a rep mid-workout, it is stored on the phone and nothing is pushed; the next sync
push, run through the real `pushNow()` transaction against a fake Firestore, carries no draft; the
cloud's echo, even one holding a newer legacy draft, leaves his workout exactly as it was. That one
path touches the persistence layer (`saveLocal`), the outbound wire (`mergeDB`), the inbound wire
(`adoptMerged`) and the differential test harness that guards the merge.

Purpose: D-04 says the draft stops crossing the wire in both directions, and D-01 says no handoff
replaces it: the draft lives only on the device that started it, so nothing in this phase builds a
cross-device path for it, in any form. The merge is the code path
that already lost real data twice. Proving the architecture end to end first, on a merge that the
frozen-legacy differential still watches, means any dead end shows up after one commit, not after
the whole boundary has been rewritten.

Output: two helpers (`stripDraft`, `keepLocalDraft`), the draft removed from every merge result, the
snapshot ring, cloud version history and JSON backup; finish and discard proven draft-free on the
wire; a fake-Firestore test harness later plans reuse.

Note for the tracking step: DRAFT-02 is only partly delivered here (the merge and listener paths).
Plan 04-02 finishes it. Do not tick DRAFT-02 in REQUIREMENTS.md after this plan.
</objective>

Calls this plan set makes where CONTEXT.md left discretion to the planner. Each is binding on
plans 04-01, 04-02 and 04-03.

- **Storage shape: keep `draft` inside the `DB` blob under `KEY`; strip it at every wire boundary.**
  RESEARCH Option A. Moving it to its own localStorage key would rename every read and write of
  `DB.draft` across the file with no compiler to catch a miss, and would need its own quota story.
  No `SCHEMA` bump and no migration: nothing rewrites rows, and D-04 wants the next ordinary merged
  write to drop the cloud field.
- **Two named helpers instead of the inline idiom repeated at every site.** `stripDraft(x)` removes
  `draft` from foreign data before it reaches `normalize()`. `keepLocalDraft(next)` puts this
  device's current draft onto whatever is about to become `DB`. Reason: research enumerated six
  sites and missed two more (the snapshot and cloud-version restores). A named helper makes the
  property greppable, and plan 04-02 adds a tripwire test that fails when a new site replaces `DB`
  without it. `mergeDB()` itself uses a plain `delete` next to the existing `wx` one, so the two
  device-local fields read the same in the merge.
- **The merge-output draft repair is removed from the live `mergeDB()`.** It repairs a value that is
  about to be deleted. The local draft is still repaired on every `normalize()` call (boot, adopt,
  import, restore).
- **Import becomes testable by extracting `importMerge(raw)` and `importReplace(raw)` (plan 04-02).**
  `importData()` cannot be driven in the harness at all: `test/harness.js` stubs `FileReader` as an
  empty constructor with no `readAsText`, so even the Merge branch is unreachable. RESEARCH
  Assumption A1 (overriding `app.__sandbox.confirm` redirects the branch) was checked during planning
  and is true, but it does not help while `FileReader` is a stub.
- **Draft functions: 25 switch to `saveLocal()`, 3 keep `save()`.** Enumerated by listing every
  top-level function in the vm sandbox whose source reads `DB.draft` and calls `save()`: 28
  functions. `pickEx` and `exPick` keep `save()` because `exEnsure()` can add a `DB.exercises` row,
  a synced collection. `finishWorkout` keeps `save()` because it lands the session in `sessions`
  (D-09). Everything else switches, including `editSession` (see plan 04-03 for why). This plan
  switches `setVal` (tracer) and `discardWorkout` (DRAFT-04); plan 04-03 switches the other 23.
