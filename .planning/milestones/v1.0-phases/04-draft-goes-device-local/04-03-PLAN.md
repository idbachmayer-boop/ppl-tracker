<decisions_recorded>
- **`editSession` switches to `saveLocal()`.** RESEARCH said it does not touch `DB.sessions`; it can:
  when the chosen session has no id it assigns one. Migrations 9 and 12 already gave every session
  an id, so that branch fires only for a row that arrived from a pre-migration source. When it does,
  the id is stored locally and reaches the cloud with the next real save, exactly as happens today
  when an edit is discarded. Opening a past workout to edit it is starting a draft (D-09), so it
  should not make this device look newest.
- **`pickEx` and `exPick` keep `save()`.** Both call `exEnsure()`, which can push a new row onto
  `DB.exercises`, a synced collection. Keeping `save()` costs one push that carries no draft.
- **`finishWorkout` keeps `save()`.** D-09: syncing happens when Finish lands the session.
- **The table test calls functions through `a.__sandbox[name]`.** Every top-level function
  declaration in the script is a property of the vm global object (checked during planning: 385 of
  them), so a 25-row table does not need 25 new harness exports. Each row asserts the lookup is a
  function first, so a renamed function fails as a readable line, not a crash.
</decisions_recorded>
