## Flagged assumptions (for Ian at verify time)

- **EXP-06 (probe category: unclassified), left unresolved on purpose.** Three presentation choices are the planner's, not Ian's: (1) the Generated line uses UTC ISO time (`2026-08-07T17:00:00.000Z`), not local time; (2) "missing" means null, undefined, blank or whitespace-only, and 0 counts as missing only on cardio minutes and distance (plan 02-02); (3) booleans such as an idea's `done` are written `true` / `false`. Confirm or correct them.
- **Android may not open the share sheet for a `.md` file.** MDN's "Shareable file types" list, which follows Chromium's allowlist, has `.txt` and `text/plain` but no `.md` and no `text/markdown` [CITED: developer.mozilla.org/en-US/docs/Web/API/Navigator/share]. On an Android phone in Chrome, `canShare` will likely return false, so D-01's fallback downloads the file instead; that is the locked behaviour and works, but the main path "share sheet → Claude app" would not open. iOS Safari is expected to share it. The manual check on Ian's phone settles which happens. If he is on Android and wants the share sheet, the fix would be revisiting D-03's `.md` filename, which is his call, so this plan does not make that change.
- **The Markdown export does not count as a backup** (RESEARCH Assumption A2). The JSON backup reminder keeps firing after a Markdown export, because only the JSON file can be restored.
- **A share failure other than a cancel downloads the file** (RESEARCH Open Question 2). Ian always ends up with the file unless he cancelled.
