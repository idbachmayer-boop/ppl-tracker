<objective>
Declare the `COLLECTIONS` registry in `index.html` as dead data at the TDZ-safe position, validate it at module-eval time, and prove through the real boot path that it survives every schema version. This plan leads the phase with the tracer slice. It goes from a literal registry, through module-eval validation, through `let DB = load()` → `normalize()` → `MIGRATIONS`, to an assertion over every declared collection for every schema from 0 to `SCHEMA`.

Purpose: the architectural risk in this phase is the temporal dead zone. A registry that throws, or that references a `const` declared further down, would be swallowed by the migration `try/catch` while `_schema` advances. That is the Migration-13/17 trap. This plan settles placement, the value rules and export metadata (REG-17) before any consumer reads the registry.

Output: `COLLECTIONS`, `collectionProblems()`, the promoted key functions (REG-04), `sessionSort`, the four format functions, the harness exports plus an optional source transform, and the boot-order regression.

Constraints on every task in this plan: no consumer (`blank`, `liveX`, `validateBackup`, `mergeDB`) changes behaviour here. Keep the suite green at every commit. Do not push to `main`: CI deploys `main` to the phone. Code reaches `main` only through a PR after the phase.
</objective>
