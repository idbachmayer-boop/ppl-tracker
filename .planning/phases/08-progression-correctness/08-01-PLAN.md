<objective>
Make the ⬆ Add weight advice judge every set that was on the card when the workout was finished
(PROG-01). A skipped set or a blank set blocks the increase (D-01). Every set must be at the working
weight (D-02). The verdict judges the latest attempt, even a fully skipped one (D-09). A bodyweight
slot at the top gets "add weight (belt) or harder variation" with no number (PROG-05, D-08).

Purpose: today `addWeightInfo` filters out skipped and blank sets before checking the top of the range,
so two top sets plus a skip still says "add weight". Ian's rule (Sep 21): "each lift needs to have all
sets done for me to progress."

Output: the add-weight helpers in `index.html`, the `blankSets` marker on newly finished entries, and
the first half of a new PROG section in `test/app.test.js`. Plan 08-02 extends that section for the
stall rule.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported backup / cloud blob → session rows | `validateBackup()` checks shape only. `w`, `r` and `blankSets` can hold anything a hand-edited file puts there. |
| session rows → viewActive HTML | The flag interpolates the unit and a computed weight into markup. |
| device ↔ cloud | Sessions union-merge by row `mtime`. A stale device or an older build can write a row without `blankSets`. |
| inline script ↔ CSP | Any script edit invalidates the pinned sha256 and blanks the app on every device. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
