# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of the visible change.** Every surface is an edit to an existing screen in `index.html`: the Lawn
screen (Care → Lawn, `viewLawn()`), the Week in Review card (Train → History, `renderWeekReview()`), and
the wording of the watering lines on Today and on the Lawn card. There is no new screen, no new action and
no new icon.

| # | Surface | Where in `index.html` (by symbol) | Decision |
|---|---------|-----------------------------------|----------|
| S1 | Lawn outlook: renamed strip, 💧 and ☔ marks, a "water" headline line, new footnote | `mowOutlookHTML()`, `mowMark()` | D-06, D-07, LAWN-04 |
| S2 | Cool-day and wet-forecast hold lines (copy only) | `lawnStatus()` water branch (to become `waterVerdict`), shown by `cLawnCard()` on Today and Lawn | D-08, D-09, LAWN-01 |
| S3 | 🌧 amount beside the pills in Lawn history, plus a one-line source note | `lawnHistory()` | D-10, D-11, LAWN-03 |
| S4 | 🚜 Mowed, 💧 Watered and 🌧 amount tags | `renderWeekReview()`, the `tags` array | D-10, D-13, LAWN-05 |
| S5 | "Offline — weather from …" note, and a label on the ↻ button | `viewLawn()` weather card header | D-14, D-15, LAWN-06 |
| S6 | "Couldn’t load weather" state with a Retry weather button | `viewLawn()`, the no-forecast branch | D-15, LAWN-06 |
| S7 | Today: no new element. Weather fetches all year; the weather card hides when the cache has no entry for today | `viewToday` weather card through `wxGlance()`; Today `onRender` | D-12, RESEARCH Pattern 8 |

The app's design system is the Nocturne `:root` tokens and the hand-written classes in the `<style>` block.
This phase reuses them. It adds **no colour token, no font, no icon, no CSS class and no `data-action`**;
every new rule is an inline `style` in the same pattern the surrounding markup already uses.

### Width check at 320, 360, 380 and 412px (Ian's phone is the primary viewport)

**Method (rendered, not estimated).** A static probe page loaded the project's real `<style>` block and the
markup in this contract, with the real `ph()` icons, at each width, in headless Microsoft Edge 157 (Windows,
Segoe UI Emoji). The probe wrapped the markup in a fixed-width box, which is exact here because the
stylesheet has no `@media` rules. 380px is the Phase 10 reference width: card content is 314px (380 − 2×16
container − 2×1 border − 2×16 card padding). **Limits:** it is a static page, not the live app, and the
emoji font is Windows', not Android's Noto Color Emoji. The phone check at the end of the phase confirms
the strip and the history row on Ian's phone.

| Claim | 320 | 360 | 380 | 412 |
|-------|-----|-----|-----|-----|
| Outlook strip: all seven cells 65px tall, no label wraps, no clipped child, with a 🚜💧 pair, a ☔💧 pair and a 🔥💧 pair on one strip | holds | holds | holds | holds |
| Outlook strip scrolls sideways (inherited behaviour: 7 × 42px cells + 3px gaps is 312px) | yes, 254px of 312px | yes, 294px of 312px | no, 314px | no, 346px |
| Pair cell: two emoji at 12px, `white-space:nowrap`, measured 33px wide in a 38px cell body | fits | fits | fits | fits |
| Lawn history row, "Wed, Sep 30" and 🌧️ 0.42" (11px, row `gap:8px`): rain text on the date's line, row 52px tall | wraps under the date, row 61px | wraps under the date, row 61px | one line, 25px clear of the Watered pill | one line, 57px clear |
| Same, widest realistic date "Wed, May 28" and a four-character amount | wraps (61px) | wraps (61px) | one line, 21px clear | one line, 53px clear |
| Same, shortest date "Sat, Aug 29" and 🌧️ 0.10" | wraps (60px) | one line, 11px clear | one line, 31px clear | one line, 63px clear |
| Same, an extreme five-character amount ("12.34") on "Wed, May 28" | wraps (61px) | wraps (61px) | one line, 16px clear | one line, 48px clear |
| Week in Review tag row with every tag at once (PUSH 1, 🎲, ⚖️, 🧎, 🏆, 🚜, 💧, 🌧️): no overflow | wraps to 4 lines | wraps to 3 lines | wraps to 3 lines | wraps to 3 lines |
| Offline note ("Offline — weather from Mon 3:40 PM", 11px): one line, left of the ↻ button, header grows 57px to 76px | one line | one line | one line | one line |
| No-forecast state (11px body, Retry weather button 8px below): body copy 2 lines, block 150px tall | 2 lines | 2 lines | 2 lines | 2 lines |

What the table does not claim: nothing was measured at 375px (the strip scrolls by 3px there, the same as
today), and Ian's emoji font was not available.

**Why the pair is 12px.** A pair at the strip's normal 16px wraps to two lines (the cell grows from 65px to
86px, a visible jump). At 13px it fits with 2.6px to spare, which a wider emoji font could lose. At 12px it
has 5px to spare, and `white-space:nowrap` means a wider font overflows into the 2px cell padding instead of
wrapping.

## Typography

**Inherited (unchanged):** the existing lawn type, which this phase does not touch: the outlook strip's
10px day label, 9px mark label and 16px mark icon; the 11px uppercase kicker; the 13px `.muted`; the 13px
`.hist-item` date (600); the 11px pills; the 30px temperature and 13px `.stat-sub`; and the 13px mow line.

New text uses 2 sizes and 2 weights:

| Role | Size | Weight | Line Height | Used by |
|------|------|--------|-------------|---------|
| Body line | 13px | 400, with `<strong>` at 700 | 1.5 | S1 water headline line (same style as the existing mow line); S6 heading (700) |

  including the new labels `water` and `both`.
- **Weights are 400 and 700 only** for new text; the history date keeps its inherited 600.
- `.muted` sets 13px, so S3's note, S5's note and S6's body each carry their own `font-size:11px` inline.

## Component Inventory

**Focal point.** The Lawn screen's focal point stays the weather card's big temperature. In the new states
the eye is not pulled away from it: S5 is a small muted line under the temperature, and S6 replaces the card

### S1: Lawn outlook (changed markup in an existing component)

`mowOutlookHTML()` keeps its `.card` shell, kicker, strip container and cell markup. Changes:

1. Kicker text becomes `Lawn outlook`.
2. The mow line stays first. A water line follows it with `margin-top:4px`, `font-size:13px`,
   `line-height:1.5`, as the mow line is styled:

   ```html
   <div style="font-size:13px;line-height:1.5;margin-top:4px">{ph('drop','lead')}Expect to water <strong>Thursday</strong> (Nov 13) — before noon or after 6pm</div>
   ```
3. The strip cell keeps its existing three rows (day label 10px/700, mark row, label row 9px/700). What
   goes in the mark row and label row is decided per day by this table. "Water day" means the day
   `nextWaterDay()` returned (at most one per strip):

   | Mow mark (`mowMark`) | Water day? | Mark row | Label | Label colour |
   |----------------------|------------|----------|-------|--------------|
   | 🚜 (mow) | no | 🚜 at 16px | `mow` | `var(--flag-fg)` |
   | ☔ (wet) | no | ☔ at 16px | `wet` | `var(--chart)` |
   | 🔥 (hot) | no | 🔥 at 16px | `hot` | `var(--warm-fg)` |
   | – (too soon, not due) | no | – at 16px | `too soon` or `not due` | `var(--muted-2)` |
   | – | **yes** | 💧 at 16px | `water` | `var(--pull-fg)` |
   | 🚜 | yes | 🚜💧 at **12px**, `white-space:nowrap` | `both` | `var(--flag-fg)` |
   | ☔ | yes | ☔💧 at 12px, nowrap | `water` | `var(--pull-fg)` |
   | 🔥 | yes | 🔥💧 at 12px, nowrap | `water` | `var(--pull-fg)` |

   The cell's other rules do not change: `flex:1`, `min-width:42px`, `text-align:center`, the next-mow
   highlight (`var(--accent-muted)` fill and the inset ring) on the cell where `d.iso === f.next.iso`.
4. The footnote paragraph is replaced by the S1 footnote copy, same element and style
   (`class="muted"`, `font-size:11px`, and its existing `margin-top:10px`, inherited).

Behaviour kept from today: the whole card is absent off-season, before a location is set, and when the
forecast has no entry for today. When mow history is unknown (`f.unknown`) the strip is still hidden, as it
is now, because those days are guesses; the mow line's existing "log your last mow to pin this down" stays,
and the water line still renders if a watering day exists. See Open Questions, item 1.

Rendered at 380px: pair cells fit on one line and the strip is 65px tall whether or not it holds a pair.

### S2: Hold lines (copy only)

No markup changes. The existing `cLawnCard()` rows show `r.text`:
- On Care → Lawn (`full`) the Watering block shows the text with the `pause` icon and the Override button.
- On Today the quiet line shows `💧 <strong>Watering:</strong> {text}` and, when `nextDueDay('water')` finds

### S3: Lawn history rain mark (changed markup in an existing component)

Each `.hist-item` row gains `style="gap:8px"` and its date `<span>` becomes a left group holding the date
and, when the day has 0.1" or more of saved rain, the amount:

```html
<div class="hist-item" style="gap:8px">
  <span style="display:flex;align-items:baseline;flex-wrap:wrap;gap:4px 8px;min-width:0">
    <span style="font-weight:600;font-size:13px;color:var(--muted)">Sat, Nov 8</span>
    <span style="font-size:11px;color:var(--text-2);white-space:nowrap" title="Estimated rainfall">🌧️ 0.42"</span>
  </span>
  <span style="display:flex;gap:6px;flex:none">{💧 Watered pill}{🚜 Mowed pill}</span>
</div>
```

- The pills group gets `flex:none` so the pills never shrink; the left group (`min-width:0`) is what gives
  way, wrapping the amount under the date when the line is full (320px always, and 360px for all but the shortest dates).
- The amount is plain text: not a `<button>`, no `data-action`, no `tap` class. The pills stay the only
  controls in the row.
- Today's row never shows a mark (today is never saved). A day under 0.1" shows no mark.
- The text is `esc()`-escaped after `toFixed(2)`.
- The source note (S3 copy) is one `<p class="muted" style="font-size:11px;margin:-4px 0 8px">` directly
  under the intro paragraph (whose own `margin:6px 0 10px` is unchanged), rendered only when at least one
  mark shows.
- The whole list stays hidden off-season (Nov to Mar), as now (D-11).

### S4: Week in Review tags (changed markup in an existing component)

Three tags are appended to the `tags` array, after 🏆 PR, each skipped on `future` days:

```html
<span style="font-size:11px">🚜 Mowed</span>
<span style="font-size:11px">💧 Watered</span>
<span style="font-size:11px" title="Estimated rainfall">🌧️ 0.42"</span>
```

- 🚜 shows only when `lawnLog[iso].mowed === true`; 💧 only when `watered === true`; 🌧️ only when the
  day's live rain row is 0.1" or more. An explicit `false`, and the `overrideWater` and `overrideMow` keys,
  never render.
- Display-only: no `data-action`, no tap target. Lawn logs are fixed in Care → Lawn (D-13).
- Shown all year, including Nov to Mar (D-11).
- The existing tag row (`display:flex; gap:8px; flex-wrap:wrap`) absorbs them; no new container.

### S5: Offline note on the weather card

Inside the left block of the weather card's top row, under `.stat-sub`:

```html
<div class="muted" style="font-size:11px;margin-top:4px">Offline — weather from 3:40 PM</div>
```

The ↻ button keeps its place on the right of the same `.row` and gains `title` and `aria-label`
`Refresh weather`.

- Shown when the cache is usable (has an entry for today), the last fetch failed, and no fetch is in flight.
  While a retry runs it reads `Retrying…`. It disappears on the first success.
- It is a note, not a control and not an alarm: muted, no icon, no colour.
- The footer line `Updated {time}.` stays as it is, so the time appears twice while offline. That is
  deliberate: the note explains why it is old; the footer is the existing line.

### S6: No usable forecast

Replaces today's `<div class="empty">Loading weather…</div>` / `Load weather` branch. A cache is **usable**
only when `daily.time` contains today's date (RESEARCH Pattern 8: the old "index 1" fallback is removed).

| State | Condition | Shows |
|-------|-----------|-------|
| Fresh | usable cache, no failure | The screen as today |
| Offline, forecast kept | usable cache, last fetch failed, idle | The screen as today, plus the S5 note |
| Retrying, forecast kept | usable cache, last fetch failed, fetching | S5 note reads `Retrying…` |
| Loading | no usable cache, fetching | `Loading weather…` in `.empty` (unchanged) |
| Not tried | no usable cache, no failure, idle | the existing `Load weather` button (unchanged) |
| Failed | no usable cache, last fetch failed, idle | the block below |

```html
<div class="empty">
  <div style="font-size:13px;font-weight:700;color:var(--text-2)">Couldn’t load weather</div>
  <div class="muted" style="font-size:11px;line-height:1.5;margin-top:4px">Check your connection, then tap Retry weather. It also tries again on its own.</div>
  <button class="btn btn-sm" style="margin-top:8px" data-action="fetchWeather">Retry weather</button>
</div>
```

The location bar above it (`map-pin` and Change) is unchanged. The Retry weather button is the same filled

| Tap Load weather | same | same | same | unchanged |
| Open Today or Care → Lawn with a stale cache | none (router `onRender` → `maybeFetchWeather`) | Fetches once per backoff window (5, then 15, then 60 minutes after repeated failures) | as above | The screen renders twice per attempt, as now; no loop |
| Device comes back online | `window` `online` event, a named function (not a `data-action`) | Retries immediately, **only** when Today or Care → Lawn is showing | as above | Same as a manual retry. On any other tab nothing happens until the next visit to Today or Lawn |

| Tap anything in Week in Review's new tags | none | none | none | none (display-only) |

Rules the rows keep (CLAUDE.md): **this phase adds no new `data-action` and no `ACTIONS` entry.** The existing
`fetchWeather` wrapper stays `{ click: () => fetchWeather() }`. No inline on-event attribute is added; no
`data-*` value carries user text; nothing stops propagation; the `online` listener is a hoisted named function
like `syncRetryNow`. Backoff state is memory-only and never in `DB`.
