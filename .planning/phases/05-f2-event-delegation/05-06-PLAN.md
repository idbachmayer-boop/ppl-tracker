<conventions_from_05_01>
Binding on this plan. Full rationale in 05-01-PLAN.md `<decisions_recorded>`.
- Markup carries `data-action="<literal name>"` plus `data-*` args. Every interpolated `data-*`
  value is `${esc(…)}`. Action names are never interpolated.
- An `ACTIONS` entry is `name: { <event>: (el, e) => … }`. A wrapper decodes `data-*`, reads numeric
  keys (`i`, `k`, `idx`, `n`, `d`, `range`) with `+el.dataset.key`, and calls the existing function
  with its existing arguments and arity. It never mentions `DB` and never calls `save()`/`saveLocal()`.
  `this` becomes `el`, `this.value` becomes `el.value`, and `event` becomes `e`.
- Block-level converted targets become `<button class="… tap">`. Keep classes and inline styles.
  Inner `<div>`s become `<span>`s with `display:block` merged into their style.
- On every rewritten template line, `${…}` attribute values carrying stored or derived data get
  `esc()` (D-09): `value=` on the set rows, stairs, backdated date and duration, and extras;
  `placeholder=` built from `repHint`.
- Existing actions to reuse: `toggleAcc` (`data-key`), `startWorkout` and `skipDay` (`data-name`).
- For every converted row, set `action` in `test/fixtures/handler-inventory.json`. Never change the
  identity fields.
- Test helpers: `controlsIn`, `fakeEl`, `fireAction`, `fireListener`, `spyOn`, `f2Corpus()`,
  `scanInlineHandlers` (from the harness), `populatedDB`, `fullDraft` (use it for every local draft:
  it pre-fills the accessories a Log render would otherwise add in memory; observation 26), and
  `spyPushes`.
</conventions_from_05_01>
