# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of the visible change.** This phase changes four things on screen and touches copy in three
places. Everything else it does (steps, rounding, merge, migration) shows up only as different numbers
in UI that already exists.

| # | Surface | Where in `index.html` | Decision |
|---|---------|-----------------------|----------|
| S1 | Equipment `<select>` on each row of Settings → Exercises | `exercisesCardHTML()` (~L2694) | EQUIP-01, EQUIP-03 |
| S2 | First-time equipment picker, six buttons, shown only for a new name the default table can't place | Main card in `viewActive` (~L1923) and weighted accessory cards in `extraCard` (~L2922) | D-04, D-16 |
| S3 | Muted equipment tag under the exercise select, e.g. "dumbbell · +2.5" | Main card in `viewActive`, directly after the `pickEx` select | D-05 |
| S4 | Copy: empty-bar deload line, warm-up rounding note, Settings intro and empty state, plate line silenced for preset EZ bars | `viewActive` coach line (~L1896), `toggleWarm` (~L2107), `exercisesCardHTML`, `platesText` | D-07, D-12, D-15 |

The app has a design system already: the Nocturne `:root` tokens and the hand-written classes in the
`<style>` block (L14-267). This contract reuses them. It adds four CSS rules (S2 only) and no new
colour, font or icon.

## Spacing Scale

Declared values for new elements (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Tag `margin-top` under the exercise select (S3); horizontal padding inside picker buttons (S2) |
| sm | 8px | Picker grid gap; picker panel top padding and prompt-to-grid gap; Settings select `margin-top` under the name (S1); picker panel `margin-top` |
| md | 16px | Not used by new elements (container and `.card` padding are inherited) |
| lg | 24px | Not used |
| xl | 32px | Not used |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions:
- **12px on the picker panel (S2):** its side and bottom padding and its `margin-bottom`
  (`padding: 8px 12px 12px; margin: 8px 0 12px`). The panel sits directly above `.lasttime` and `.coach`,
  which run on a 10-12px rhythm. A 16px gap would read as a section break inside the card, and 8px would
  crowd the "Last time" line. 12px is a multiple of 4. It is not in the standard scale, so it is
  confined to this one rule.
- **44px minimum height on each picker button (S2).** It is a mid-set, one-handed tap target. Existing
  `.day-btn` is about 33px tall, which is too small here.
- **88px minimum column width in the picker grid** (`minmax(88px, 1fr)`), so "bodyweight" never
  overflows. At about 380px (Ian's phone) the grid is 3 × 2. Below about 300px of card content width it
  drops to 2 columns.
- **Inherited, not re-specified:** the existing classes reused here keep their own off-grid values
  (`.ex-body` 14px padding, `.lasttime` 6/10px margins, `.hist-item` 12px rows, `.btn-sm` 6/11px,
  `select` 9/10px padding, 1.5px borders). This phase does not touch them.

## Typography

New text in this phase uses 4 sizes and 2 weights. Existing text it sits next to keeps its current
styles.

| Role | Size | Weight | Line Height | Used by |
|------|------|--------|-------------|---------|
| Body (control) | 14px | 400 | normal (inherited `select` rule) | Settings equipment `<select>` (S1), same as every other select in the app |
| Label (button) | 13px | 600 | normal (inherited `.day-btn`) | The six picker buttons (S2) |
| Meta | 12px | 400 | 1.5 | Equipment tag (S3, via `.ex-meta`); picker prompt and hint (S2) |
| Note | 11px | 400 | normal | Warm-up rounding note (S4), same size as the line it replaces |

- **No new sizes:** all four sizes are reused from existing controls, and none is a new choice:
  - 14px from the global `select` rule;
  - 13px from `.day-btn`;
  - 12px from `.ex-meta`, `.lasttime` and `.coach`;
  - 11px from the warm-up note this phase rewrites.
- **Weights:** 400 and 600 only for new text. The exercise name inside the picker prompt is **not**
  bolded. It is set off with curly quotes (“…”), the way `resolveTypedName`'s confirm already quotes
  names.
- **Inherited (unchanged):** Settings row names stay `<strong>` 13px/700, the "· N sessions" count
  stays 11px muted, and the coach line stays 12px/1.5 with its 700 `.coach-btn`.

Accent reserved for:

stays quieter than the ⬆ Add weight flag (`--flag-*`) and the range badge.

Other tokens this phase uses, all existing:

- The plate line's "(+x can't load)" stays `var(--warm-fg)`. It is unchanged, but it now appears on
  Preacher curl too.

## Component Inventory

**Focal point.** When the picker (S2) is showing, it is the card's main focal point: the only inset
panel on the card, carrying the one accent-filled button. The rest of the time the set rows are the
focal point. The tag (S3) is deliberately the quietest element on the card: muted 12px, no border, no
fill, below both the ⬆ Add weight flag and the range badge.

### S1 — Settings → Exercises row (modified `.hist-item`)

```html
<div class="hist-item" style="align-items:flex-start">
  <span style="min-width:0;flex:1">
    <strong style="font-size:13px">{esc(name)}</strong>
    <span class="muted" style="font-size:11px">· {n} session{s}</span>
    <select data-action="setExEquip" data-id="{esc(id)}" aria-label="Equipment for {esc(name)}"
            style="display:block;width:auto;min-width:140px;margin-top:8px">
      <option value="{esc(t)}" {selected}>{EQUIP_LABEL[t]}</option> × 6, in EQUIP_TYPES order
    </select>
  </span>
  <button class="btn btn-sm btn-ghost" data-action="renameExercise" data-id="{esc(id)}">{ph('pencil-simple')}Rename</button>
</div>
```

- The select sits **under** the name, on its own line, and is never squeezed beside the Rename button.
  At about 314px of card content width, three controls on one line would leave long names like "Chest
  Supported T-Bar Row" about 90px.
- `align-items:flex-start` keeps Rename level with the name line.
- The selected option is `equipOf(name)`: the stored type if it is valid, else the name-rule guess.
- A listed key with no registry row (`exRow(id)` is null; Rename already bails for it) renders **no
  select**. In its place goes a plain line, `<div class="muted" style="font-size:12px;margin-top:8px">{EQUIP_LABEL[equipOf(name)]}</div>`.
- The select uses the default `select` styling (14px, 9/10px padding, about 38px tall, `--surface-2`).
  It is the same control as the merge selects above it.

### S2 — First-time equipment picker (new; the only new CSS)

New rules, added to the `<style>` block next to `/* Exercise log card */`:

```css
.equip-ask { background: var(--surface-2); border: 1px solid var(--border); border-radius: 8px; padding: 8px 12px 12px; margin: 8px 0 12px; }
.equip-ask p { font-size: 12px; line-height: 1.5; color: var(--text-2); margin-bottom: 8px; }
.equip-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(88px, 1fr)); gap: 8px; }
.equip-grid .day-btn { min-height: 44px; padding: 8px 4px; width: 100%; }
```

Markup, directly after the card's exercise `<select>` (main card: after `data-action="pickEx"`;
accessory card: after `data-action="exPick"`) and before `.lasttime`:

```html
<div class="equip-ask" role="group" aria-label="Equipment for {esc(name)}">
  <p>What equipment is “{esc(name)}”?<br><span class="muted" style="font-size:12px">Sets its weight step. Tap one to confirm — change it any time in Settings → Exercises.</span></p>
  <div class="equip-grid">
    <button class="day-btn {active if t===equipOf(name)}" aria-pressed="{true|false}"
            data-action="pickExEquip" data-id="{esc(id)}" data-equip="{esc(t)}">{EQUIP_LABEL[t]}</button> × 6
  </div>
</div>
```

- **Order:** barbell, EZ bar, dumbbell / machine, cable, bodyweight. At 3 columns that gives free
  weights on the first row and stack or body on the second.
- **Pre-selected:** the `equipGuess(name)` button carries `.active` and `aria-pressed="true"`. It shows
  what the exercise is already set to (`equipAt 0`). Tapping it confirms it.
- **Shows only when** the card's current exercise id is in the in-memory `equipAsk` set. That holds
  after `pickEx`/`exPick` "+ Custom…" created a **new** registry row whose name is not in
  `EQUIP_DEFAULTS` (D-16). It never shows for program names, names already in the registry, or the
  "Did you mean …" path that resolves to an existing row.
- **Not on time-based accessory cards** (`unit:'sec'`, e.g. Dead hang). They log no load, so a step
  means nothing there. The row keeps its guess.
- **While the picker shows, the card's tag (S3) is hidden.** The highlighted button already states the
  type.
- The picker does not block logging. Set rows, notes and Finish stay usable below it.

### S3 — Equipment tag (new markup, existing class)

```html
<div class="ex-meta" id="equip-tag-{i}" style="margin-top:4px">{esc(tagText)}</div>
```

- Goes directly after the main card's `<select data-action="pickEx">` and before `.lasttime`. That puts
  it under the exercise name, which lives in the select.
- `.ex-meta` gives it 12px in `--muted`. No icon, no pill, no border: it should be easy to find when
  something looks wrong and easy to ignore when nothing does.
- **Step source:** `weightStep(entry.name, heaviest live weight on the card)`, the same "heaviest
  entered weight" rule the plate line uses. With no weight entered it uses 0 (dumbbell → +2.5).
- **Live update:** `updPlates(i)` also rewrites `#equip-tag-{i}`, **before** its existing early return
  for cards with no plate line. Typing 65 into a dumbbell card then flips the tag to "+5" with no
  re-render, and `ACTIONS.setWeight` needs no change.
- Main exercise cards only. Not on collapsed cards (they keep their one-line summary) and not on
  accessory cards, where no step-driven advice renders.

### S4 — Changed lines in existing components

- **Deload coach line** (`.coach.deload`): when `entry.deload` is set and the deload could not go
  lighter, because the last working weight is already the empty bar (D-15), the text is the D-15 line
  plus the existing `undo` button. Otherwise the line is unchanged. The planner owns how the card knows
  it was the empty-bar case. It must not add a field that `finishWorkout` copies into a session.
- **Warm-up note** (`toggleWarm`): still shown only when `bar == null`, in the same
  `<div class="muted" style="font-size:11px;padding-top:4px">`. The text is chosen by type and unit from
  the Copywriting table.
- **Plate line** (`#plates-{i}`): Preacher curl now renders one (EQUIP-06). For EZ style the D-07
  silence applies, and the container stays in the DOM with empty content, as it already does for an
  empty sled.

## Interaction Contract

| Interaction | Event → ACTIONS entry | Calls | Persists | Feedback |
|-------------|-----------------------|-------|----------|----------|
| Change the Settings select | `change` → `setExEquip` (`el.dataset.id`, `el.value`) | `setExerciseEquip(id, type)` | `save()` (synced registry row, `equipAt = Date.now()`, `touch()`) | `render()`; toast `Equipment set ✓` |
| Tap a picker button | `click` → `pickExEquip` (`el.dataset.id`, `el.dataset.equip`) | `setExerciseEquip(id, type)` and remove `id` from `equipAsk` | `save()` | `render()`: the picker disappears, the tag appears with the chosen type; toast `Equipment set ✓` |
| Ignore the picker | none | none | none (the row already holds the guess, `equipAt 0`) | The picker stays until tapped, until the slot switches to another exercise, or until the app reloads (`equipAsk` is in-memory UI state, never stored) |
| Type a weight on a card | existing `input` → `setWeight` | existing `updPlates(i)` | unchanged (`saveLocal()`) | Plate line and tag update live |
| Tap `Deload −10%` | existing | `deloadExercise(i)` | unchanged (`saveLocal()`) | Step-rounded weights fill in; the coach line shows the standard text or the D-15 text |

Rules every row above keeps (CLAUDE.md): no inline on-event attribute, no action name built at runtime,
wrappers decode `data-*` and never touch `DB` or persist, nothing stops propagation, every `data-*` and
`aria-label` value goes through `esc()` inside double quotes, and labels come from `EQUIP_LABEL`, never
from the stored `equip` string. `setExerciseEquip` never reads `DB.draft`, so it does not join
`DRAFT_PUSHERS`.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*

> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 9 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Settings → Exercises list (S1) | ✅ covered | With no logged exercise, the card renders the Copywriting Contract's empty-state body, which now names equipment, and no select |
| populated | Settings → Exercises list (S1) | ✅ covered | Every listed row with a registry row renders one select with `equipOf(name)` selected, still sorted by use, so Ian's frequent lifts (about 38 in his export) stay at the top |
| partial | Settings → Exercises list (S1) | ✅ covered | A listed key with no registry row renders its guessed type as plain muted text and no select (S1), the same rows Rename already ignores |
| error | Settings select (S1), picker buttons (S2) | ✅ covered | An invalid or hostile stored `equip` renders as the name-rule guess (`equipOf`), never as raw text. A type outside `EQUIP_TYPES` arriving from a control is refused with no write and no toast (Copywriting Contract, Error state) |
| error | Equipment tag (S3) | ✅ covered | The tag text is built only from `EQUIP_LABEL` plus a numeric step through `esc()`. A missing or invalid type falls back to the guess, so the tag always reads as one of the documented formats |
| zero-one-many | Picker (S2) across cards | ✅ covered | Each card shows its own picker only for its own new id. Two new custom names on two cards give two independent pickers, and a tap on one leaves the other in place. The Settings session count keeps its existing `session`/`sessions` plural |
| long-text | Settings row name (S1), picker prompt (S2) | ✅ covered | Names wrap inside the `flex:1; min-width:0` column, with the select on its own line beneath. The prompt is a wrapping `<p>`. Neither truncates |
| overflow | Picker grid (S2) | ✅ covered | `repeat(auto-fit, minmax(88px, 1fr))` gives 3 × 2 at about 380px and 2 × 3 below about 300px of content width, so "bodyweight" (the longest label) never overflows a button |
| long-text | Equipment tag (S3) | ✅ covered | The longest possible tag is "bodyweight" or "dumbbell · +2.5", well under one line at 12px. It never wraps on a 380px phone |
| populated | Picker (S2), tag (S3), Settings (S1) rendered on the phone | 🧪 backstop | On Ian's Android PWA at about 380px: the picker shows 3 × 2 with each button at least 44px tall, the guess highlighted, and the tag legible under the select; Settings rows stack the select under the name. Verified in the end-of-phase real workout (Settings → This version first) |

Not applicable (dismissed with reason):
- **loading:** every surface renders synchronously from local `DB`, with no fetch on any path this
  phase adds. Sync loading is the existing sync UI's job.
- **empty, for the tag and picker:** the tag always has a type (the guess at minimum), and the picker
  appears only when there is a row to set.
