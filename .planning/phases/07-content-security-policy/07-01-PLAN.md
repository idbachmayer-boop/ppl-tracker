<objective>
Move the build stamp out of the inline `<script>` and into `<meta name="ppl-build">` in `<head>`,
read it at runtime, and retarget the deploy job and the tests (D-08). This is the stamp move Ian
ships and confirms on both devices before any CSP code goes live (D-09).

Purpose: the deploy job currently rewrites a string inside the inline script after checkout. Once
Phase 7 pins that script by sha256, that rewrite makes production refuse to run the app while every
local check passes. RESEARCH reproduced it in Chrome: blank page, `appBooted: false`. Moving the
stamp into a meta attribute takes the deploy-time rewrite out of the hashed bytes for good.

Output: the meta, the runtime read, the harness change, the retargeted deploy step, the
`deployStamp()` replay helper with guards that are shown to go red, and a recorded deployable-unit
tip sha.
</objective>
